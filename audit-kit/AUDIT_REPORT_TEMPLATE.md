# StegGate Boundary Audit Report

This template defines the human-readable projection generated by `tools/build_audit_package.py`. The generated report is derived from canonical machine-readable evidence and is never an authority source.

## Required sections

1. **Audit identity** — package id, profile, fixture/real-boundary classification.
2. **Candidate binding** — candidate id, canonical `sha256:` id, action/transition reference.
3. **Decision reconstruction** — decision, registered reason code and registry interpretation.
4. **Receipt reconstruction** — receipt id/hash and `authority_effect`.
5. **Evidence pack** — manifest id, object count, immutable object commitments, sensitive-content posture.
6. **Achieved assurance** — identity, signatures, trust anchor, source evidence and capability-construction assurance actually observed/claimed by the pack.
7. **Coverage** — explicit coverage declaration from the pack.
8. **Independent verification** — first-language and second-language verifier commands and agreement state.
9. **Trust assumptions** — assumptions carried by the evidence pack.
10. **Non-claims and limitations** — explicit statements preventing fixture integrity from being rendered as customer validation, execution authority, publication/release authority, deployment status, compliance proof or standards certification.

## Binding rule

The generated Markdown report is a projection of `audit-report.json`. `package-manifest.json` binds the report, evidence-pack manifest, source evidence objects and verifier/tool inputs by SHA-256. If any bound object changes without regeneration, package verification must fail.

## Authority boundary

A PASS means the supplied evidence can be reconstructed under the declared fixture/profile contract. It does not establish the truth of external assertions and does not grant permission for any consequential transition.
